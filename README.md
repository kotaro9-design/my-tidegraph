# my tide-graph（Google Apps Script Web アプリ）

作成：[kotaro9](https://x.com/kotaro9_lures)

スマホの現在地から最寄りの検潮所を選び、**推算潮位（天文潮）** と **実測潮位** を重ねて表示します。

- 上げ／下げ◯分（直前の干潮・満潮から次の満潮・干潮までを 10 等分した経過）
- 現在の実測潮位・潮位偏差（実測 − 推算）
- 次の満潮・干潮の時刻と高さ（偏差で補正した高さも表示）
- その日の満潮・干潮一覧、潮名（旧暦の日付から）、月齢（月の形のアイコン付き）・月輝面（％）と旧暦（閏月を含む）。グラフに月の出・南中・月の入りの時刻を表示
- 潮位グラフ（推算・実測・偏差補正予測）と潮位偏差グラフ。タップすると、その時刻の値を表示します
- 表示範囲（3日／1日／前後12時間／前後6時間／前後3時間／前後1時間）、日付の切替、5 分ごとの自動更新
- 高さの基準を「潮位表基準面」と「TP」で切替
- 現在地の天気（気象庁の天気予報：天気・降水確率・予報の風・波・明日の天気）と気温
- 地上の風向・風速（最寄りのアメダスの実況、10 分ごと）と、その日の最大瞬間風速
- 風の推移・予報：現在地を中心にした地図（地理院タイル）の上に、3時間ごとの風向矢印と風速を表示（過去はアメダスの実況、先は Open-Meteo の気象庁モデル予報）
- 釣果の記録：写真は「カメラで撮影」（撮影した写真は共有画面または長押しでスマホの写真フォルダに保存）か「写真フォルダから選ぶ」で最大3枚。撮影日時（EXIF。無ければファイルの日時）を釣果の日時に、写真の位置情報から最寄りの潮位観測所とグラフの日付を自動で合わせます。魚種・サイズ・重さ・匹数・場所・釣行スタイル・釣り方・ヒットレンジ・ルアー・タックル（ロッド／リール／ライン／リーダー）・メモを入力すると（魚種・場所・ルアー・タックルは過去の入力をボタンで選べる）、その時刻の潮・潮位・偏差・天気・風・降水量・河川水位を添えた投稿文を作ります。アングラーズ等へは「写真と文章を共有」または「文章をコピー」、Google カレンダーへは予定作成画面を開いて登録（保存は本人。写真そのものは付けられないため、写真フォルダのファイル名と撮影日時、Google フォトの撮影日検索リンクを予定に記載）
- 近くの河川の水位（国土交通省「川の防災情報」、10 分毎）を潮位グラフに重ねて表示（表示／非表示を切替可）。観測所は自動（現在地から一番近い観測所。最新値が欠測中の観測所は除く）のほか、近くの観測所一覧から選択可
- 水質：現在地から 10km 以内に水質観測所があるときだけ、水温・塩分濃度を表示（上層・下層など水深別の観測は層ごと）
- 日の出・日の入り・薄明（常用薄明／天文薄明、計算値）を表示。グラフでは夜間を網かけし、朝マヅメ（常用薄明の始まり〜日の出30分後）・夕マヅメ（日の入り30分前〜常用薄明の終わり）を色の帯で表示
- 潮位グラフに上げ／下げ 1・3・5・7・9分の線（満潮・干潮の間を10等分した位置）を表示

## データ源

| 用途 | 出典 |
| --- | --- |
| 観測地点・実測潮位（15 秒値 → 1 分平均）・潮位偏差・毎時の推算潮位 | 気象庁「潮位観測情報」（気象庁・国土交通省港湾局・海上保安庁・国土地理院 等の検潮所 166 地点） |
| 満潮・干潮の時刻と潮位 | 気象庁「潮位表」 |
| 直近の実測潮位（速報） | 海上保安庁「リアルタイム験潮データ」（Web ページの 5 分毎瞬間値。暫定値） |
| 河川水位 | 国土交通省「川の防災情報」（現在地（GPS）から一番近い水位観測所。位置が取れない場合は表示中の潮位観測所の位置から。T.P. 基準） |
| 水温・塩分濃度 | 国土交通省「川の防災情報」の水質観測所（1時間ごと。位置が未登録の観測所は国土地理院の住所検索で補完） |
| 天気・降水確率・予報の風・波 | 気象庁「天気予報」（現在地の市区町村 → 一次細分区域） |
| 風向・風速・最大瞬間風速・気温 | 気象庁「アメダス」（現在地に最も近い、風を観測している地点） |
| 風の予報（3時間ごと） | Open-Meteo（気象庁 MSM/GSM モデルの地点値、CC BY 4.0） |
| 海面水温（1時間ごと・推定） | Open-Meteo Marine API（解析・予報モデル、約8km格子、CC BY 4.0）。ブラウザから直接取得 |
| 背景地図 | 国土地理院「地理院タイル」（淡色地図） |
| 現在地の市区町村の判定 | 国土地理院「逆ジオコーダ」（海上などで判定できないときは、観測地点の市区町村を使います） |

実測値は速報値です。気象庁の公開は 15〜20 分程度遅れるため、直近の分は海上保安庁「リアルタイム験潮データ」（5 分毎、公開の遅れ 2〜3 分、89 地点）で補っています。基準面の差は、重なる時間帯の値の差から自動で合わせます。同じ地点の速報が無い地点（港湾局の検潮所など）では、30 km 以内の速報のある地点の最新の潮位偏差を使って、現在の潮位と偏差補正予測を推定します。
潮位表に対応する地点が無い場合は、毎時の推算潮位をスプライン補間して満干潮を算出します（目安）。

## ファイル構成

- `Code.gs`：サーバー側（データ取得・解析・キャッシュ）
- `index.html`：画面（グラフは Canvas に描画し、外部ライブラリは使いません）
- `appsscript.json`：マニフェスト（タイムゾーン、Web アプリ設定）
- `tools/build-pages.js`：GitHub Pages 用の `docs/` を `index.html` から作るスクリプト
- `docs/`：GitHub Pages で公開する画面（生成物。直接編集しない）

### バージョン

- 画面下と利用ガイドに表示するバージョンは、`index.html` の `APP_VERSION` / `APP_DATE` です
- 番号は「大きな変更.機能追加.修正」（例：1.2.3）。更新したら [CHANGELOG.md](CHANGELOG.md) に内容を書き、GitHub に `v1.2.3` のタグを付けます
- 利用ガイドは `index.html` の `<dialog id="guideDlg">` にあります。機能を変えたらガイドも直します

### 更新の流れ

1. `index.html` / `Code.gs` を編集
2. `clasp push` → `clasp update-deployment <デプロイID>`（Apps Script の画面とデータ取得を更新）
3. `node tools/build-pages.js` で `docs/` を作り直す
4. `git commit` → `git push`（数分で GitHub Pages に反映）

GitHub Pages の設定：リポジトリの Settings → Pages → Source「Deploy from a branch」、Branch「main」「/docs」。

## デプロイ手順

### A. ブラウザだけで行う場合

1. <https://script.google.com> で「新しいプロジェクト」を作成します
2. `コード.gs` の中身を、このフォルダの `Code.gs` の内容に置き換えます
3. 「＋」→「HTML」で `index` という名前のファイルを作り、`index.html` の内容を貼り付けます
4. 「プロジェクトの設定」で「appsscript.json をエディタで表示する」をオンにし、`appsscript.json` の内容に置き換えます
5. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」を選び、次のように設定します
   - 次のユーザーとして実行：自分
   - アクセスできるユーザー：全員（自分だけが使う場合は「自分のみ」）
6. 初回は外部 URL へのアクセスを承認します。発行された `/exec` の URL をスマホで開き、ホーム画面に追加してください

### B. clasp を使う場合

```sh
clasp login
clasp create --type webapp --title "潮汐グラフ" --rootDir .
clasp push
clasp deploy
```

コードを更新したら `clasp push` を実行し、続けて `clasp deploy -i <デプロイID>` で同じ URL のまま更新できます。

## 使い方

- 地点一覧の上部で「すべて」と「海上保安庁サイトの観測所のみ」（速報が2〜3分遅れで届く89地点）を切り替えられます。現在地からの最寄り選択にも反映されます
- 地点名をタップすると、地点一覧（現在地から近い順）から選べます。検索もできます
- 右上の ◎ ボタンで、現在地から最寄りの地点に切り替えます
- URL に `?st=124431` のように地点コードを付けると、その地点を開きます（ブックマーク用）
- 前回表示した地点・表示範囲・高さの基準は、端末に保存されます

## 注意

- Apps Script の Web アプリは iframe 内で表示されるため、端末やブラウザによっては位置情報の許可が求められない、または取得できないことがあります。その場合は前回の地点（初回は東京）を表示するので、地点一覧から選んでください
- データ取得はサーバー側でキャッシュしています（実測 60 秒、推算・潮位表 6 時間）
- 河川水位・水質はサーバー側で 15 分（観測所情報・観測所の選択肢は 6 時間）キャッシュし、近くの利用者で共有します。「自動」で選んだ観測所は約1km四方ごとに1時間記憶し、次からはその観測所だけを確認します（取得回数を抑えるため、選択肢には現在水位を表示せず、水位表示がオンで選択欄に触れたときだけ読み込みます）。海上保安庁の速報は3分キャッシュします
- 気象庁・Open-Meteo・国土地理院のデータは、Apps Script の URL Fetch の1日の上限を節約するため、ブラウザが直接取得してサーバーに渡します（`callWithPre`）。ブラウザで取れなかったときはサーバーで取得します。海上保安庁と川の防災情報は CORS の都合でサーバー側で取得します

### 利用状況のモニタリング（Monitor.gs / admin.html）

- 画面はデータ取得の通信に利用状況（匿名ID・潮位観測所・約10km単位の地域・機能・エラー）を相乗りさせて送り、サーバーはキャッシュにまとめて1時間ごとのトリガー（`flushMonitor`）でスプレッドシート「my tide-graph 利用状況」に書き込みます
- 初回だけ Apps Script のエディタで `setupMonitor` を実行します（スプレッドシート・合言葉・トリガーを作成し、管理画面の URL を実行ログに出力）
- 管理画面：`/exec?admin=合言葉`（合言葉はスクリプト プロパティ `ADMIN_KEY`）

### 不正利用への対策

- 位置（日本の周辺）・日付（前後400日）・地点コードなどの入力値をチェックします
- ブラウザから渡されたデータは、その利用者への応答にだけ使い、共有キャッシュには入れません（偽データが他の利用者に表示されないように）。地点一覧・年間の推算・潮位表などの基本データはサーバーで取得して共有します
- サーバーからの外部取得は 1時間 2,500 回・1日 18,000 回まで、ブラウザで取れなかった分の代行は 1時間 300 回までに制限します（`FETCH_LIMIT`）。超えた場合はキャッシュ済みのデータだけを表示します
